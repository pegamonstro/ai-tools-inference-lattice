# Protocol Spec: inference.v1

**Version:** 1.0
**Status:** Draft (Phase 1)

The `inference.v1` protocol is a routing-aware extension of the OpenAI Chat Completions API. It allows clients to express intent (privacy, latency, parallelism) while remaining compatible with standard LLM tooling.

## 1. Interface

- **Endpoint**: `/v1/chat/completions`
- **Method**: `POST`
- **Format**: `application/json`

## 2. Request Envelope

The request is a standard OpenAI Chat Completion request, extended with a `routing` object.

### Request Schema

```json
{
  "model": "string", // Model hint or alias (e.g., "local-brain", "cloud-coder")
  "messages": [
    { "role": "user", "content": "..." }
  ],
  "routing": {
    "privacy": "LOCAL_ONLY" | "LOCAL_PREFERRED" | "CLOUD_ALLOWED",
    "latency_class": "interactive" | "batch",
    "parallelism": number, // 1 = single, >1 = fan-out (batch)
    "request_id": "string", // UUID for tracing across Control/Gateway
    "provider_params": {
      "reasoning_effort": "low" | "medium" | "high",
      "max_budget": number
    }
  },
  "stream": boolean,
  "max_tokens": number,
  "temperature": number
}
```

### Routing Metadata Definitions

- `privacy`:
  - `LOCAL_ONLY`: Hard gate. Must execute on Mac. Fail closed if unavailable.
  - `LOCAL_PREFERRED`: **Not implemented.** The intended meaning was "prefer Mac,
    fall back to cloud if Mac is unavailable", but the Control plane's policy
    table has never implemented it: it routes `LOCAL_ONLY` to the local gateway
    with no fallback, and everything else by latency class. A request carrying
    `LOCAL_PREFERRED` is therefore treated as "anything else" — routed by its
    latency class, not by this level's stated preference. Recorded here so the
    drift is visible rather than rediscovered; do not implement it without a
    design change.
  - `CLOUD_ALLOWED`: Any provider.
- `latency_class`:
  - `interactive`: User is waiting. Cloud-first routing to minimize wall-clock.
  - `batch`: Throughput-bound. Local-first routing to utilize free parallelism.
- `parallelism`:
  - `1`: Standard turn.
  - `n`: Split the task into `n` independent units (if the Control plane supports decomposition) or execute `n` versions for consensus/sampling.
- `request_id`:
  - Generated by the client or Control plane to trace the request through the Lattice.

## 3. Control Plane Logic (The Routing Decision)

When a request arrives at the Control plane (RPi4), it evaluates:

1. **Privacy check**: If `LOCAL_ONLY` and Mac is down $\rightarrow$ `503 Service Unavailable`.
2. **Resource check**:
   - If `latency_class == interactive` $\rightarrow$ Route to Cloud (subject to 3-parallel cap).
   - If `latency_class == batch` $\rightarrow$ Route to Local (Mac).
3. **Concurrency check**:
   - If Cloud is at 3/3 $\rightarrow$ queue request or spill to Local (if privacy allows).
4. **Model Mapping**: Map the `model` alias (e.g., `local-brain`) to the specific resident model on the Gateway (e.g., `granite4:3b`).

## 4. Gateway Logic (The Execution)

The Gateway (Mac) receives the routed request from the Control plane:

1. **Memory check**: Check if the target model is resident.
2. **Swap avoidance**: If loading the model would trigger swap (per memory pressure thresholds), return `429 Too Many Requests` or `503` to signal the Control plane to reroute or queue.
3. **Execution**: Forward to Ollama `/api/chat` or `/v1/chat/completions`.
4. **Response**: Return the OpenAI-compatible response.

## 5. Response Envelope

Standard OpenAI response.
```json
{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "created": 123456789,
  "model": "granite4:3b",
  "choices": [
    {
      "index": 0,
      "message": { "role": "assistant", "content": "..." },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 20,
    "total_tokens": 30
  }
}
```

## 6. Exit Test (Phase 1)

A reference client (Go) sends a request with `routing: { privacy: "LOCAL_ONLY", latency_class: "interactive" }` to a reference server (Go).
- The server must correctly identify the intent.
- A round-trip JSON exchange must complete without schema errors.
